## 1. Риск-реестр

Риски нашего агента, а не «ИИ вообще». Каркас — три вопроса к каждому действию агента (OWASP LLM06:2025): нет ли
лишней **функции**, лишнего **права**, лишней **самостоятельности**; плюс работа за пределами условий, в которых
систему валидировали.

## 2. Rollout: shadow → HITL → autonomous

Стадия задаётся одной строкой конфигурации — `CFG_ROLLOUT_STAGE` (BRD-04), так что переход и откат стадии — смена
значения, а не переделка системы.

| стадия | как работает (код) | кто видит BRD | точка человека |
|---|---|---|---|
| **shadow** | агент проводит интервью, BRD-04 кладёт BRD в папку проверки (`CFG_REVIEW_FOLDER_ID`); заказчик получает «ответы переданы команде», ссылки нет. Параллельно аналитик ведёт ту же заявку по-старому (встреча и свой BRD) | только команда AIOps («BRD в тени — сравнить с BRD аналитика») | проверяющий AIOps сравнивает BRD агента с BRD аналитика |
| **HITL** | аналитик не участвует; BRD-04 кладёт BRD в папку проверки, заказчик получает «BRD на проверке», сессия `awaiting_review`; проверяющий запускает **BRD-08**: `approve` — документ переносится в wiki и заказчику уходит ссылка; `return` — заказчик получает вопросы и отвечает в той же беседе | AIOps, затем — после утверждения — заказчик и общая wiki | экран BRD-08 (решение approve / return) по каждому BRD |
| **autonomous** | BRD публикуется в папку-wiki сразу, заказчик и команда получают ссылку (как в демо) | все | согласование BRD людьми (To-Be 4) остаётся всегда; мониторинг и условия отката — в силе |

### Критерии перехода

Базовые значения — из наших прогонов: серия пяти прогонов 14.10 — 5/5 успешных, 0 выдуманных фактов (153 ссылки
сошлись); eval-набор 16.10 — 12/13 по коду, 13/13 у человека, в обоих прогонах.

| переход | критерий (все условия сразу) | чем считаем |
|---|---|---|
| **shadow → HITL** | (1) eval-набор BRD-97 **на Qwen3.8-27B** — не меньше 12 из 13 по коду и 0 провалов у человека; (2) **10 заявок подряд** в тени: **0 выдуманных фактов** и совпадение ключевых полей с BRD аналитика **≥ 90 %** (9 из 10 заявок совпали по всем полям: тип batch/online, статусы MLflow и GitLab, класс данных, наличие риска внешних API, список открытых вопросов) | лист `eval_results`; таблица сравнения тени, которую ведёт проверяющий (заявка · поле · агент · аналитик · совпало) |
| **HITL → autonomous** | (1) **20 BRD подряд** утверждены через BRD-08 **без существенных правок** — доля approve с первого раза **≥ 90 %** (не больше 2 return из 20); (2) **0 критических ошибок** за эти 20 (выдуманное требование, неверный статус MLflow/GitLab, вынос данных); (3) доля возвратов после согласования (To-Be 4) **≤ 10 %** — KPI To-Be; (4) медиана активного времени заказчика на интервью **≤ 45 мин** | решения BRD-08 (`brd_sessions`, сообщения «BRD утверждён / возвращён»), `brd_registry.status`, метки времени реплик в `brd_sessions.history` |

## 3. План эксплуатации

### Кто чинит

| что сломалось | кто чинит (роль) |
|---|---|
| логика агента, промпты, воркфлоу BRD-*, база знаний, ручная очередь | **руководитель AIOps** — владелец сервиса |
| платформа: n8n self-hosted, внутренний API моделей на пуле H200, S3 / векторная БД | **дежурный DevOps / команда платформы** |
| инцидент с данными (вынос за периметр, доступ постороннего) | **служба ИБ** вместе с владельцем сервиса |
| wiki, Rocket.Chat, сервисные учётки | **ИТ** |

**«Агент упал в выходные — кто чинит?»** На пилоте режим 24/7 не нужен. Алерт приходит в чат саппорта (BRD-00);
дежурный DevOps или владелец сервиса включает **kill-switch** (`MAINTENANCE = true`) — заказчики видят «Сервис временно
недоступен, беседа сохранена»; ремонт — в первый рабочий день, владелец сервиса.

### Что мониторим (указатели на логи из раздела 6, [eval-suite.md](eval-suite.md))

| что | где |
|---|---|
| шаги и ошибки каждого прогона | n8n → *Executions* BRD-03 (реплики) и BRD-04 (генерация), метка `outcome = done / limit_stopped / error` |
| сбои | лист `errors` и алерты в чате саппорта (BRD-00) |
| остановки по пределу | лист `manual_queue` и предупреждения в чате команды (BRD-07) |
| качество генерации | лист `brd_runs`: вердикт валидатора, раунды исправления, `rollout_stage` |
| стоимость | выгрузка вызовов модели (в демо — OpenRouter Activity; во внутреннем контуре — метрики внутреннего API) |
| общая картина за сутки | дайджест BRD-06: интервью, BRD, `needs_review`, ждущие утверждения (HITL), база знаний, ошибки |

Eval-набор — критерий перехода стадий и обязательная проверка перед любым изменением, а не предмет ежедневного мониторинга.

### Когда откатываем

| сигнал | куда откатываемся |
|---|---|
| любая критическая ошибка: выдуманное требование в утверждённом BRD, неверный статус MLflow/GitLab, вынос данных за периметр, доступ постороннего | **kill-switch** (стоп) → разбор → возврат на **shadow** |
| за 2 недели на autonomous возвраты после согласования **> 20 %** или ≥ 3 return подряд в HITL | на одну стадию назад (autonomous → HITL, HITL → shadow) |
| eval-набор после изменения промпта, модели или воркфлоу — **меньше 12 из 13** по коду или провал у человека | откат изменения (прежняя версия из git) |
| **> 3** строк `manual_queue` за неделю или **> 5** ошибок BRD-00 за сутки | HITL (каждый BRD — через проверяющего) до разбора причины |

### Как откатываем

| механизм | как включить | скорость |
|---|---|---|
| **kill-switch** | BRD-03 → узел *Config* → `MAINTENANCE = true` → Publish (или `CFG_MAINTENANCE=true` в `.env` и переимпорт); крайний вариант — снять BRD-03 с публикации | секунды |
| **смена стадии** | `CFG_ROLLOUT_STAGE` (BRD-04 → *Config* → `ROLLOUT_STAGE`) → Publish | секунды |
| **откат версии воркфлоу** | импорт прежнего `workflows/*.json` из git (`git checkout <коммит> -- workflows/`, `deploy.py --dry-run`, Import from File) | минуты; проверено на практике: так возвращали модель после cost-attack и переимпортировали BRD-04 при каждой итерации |
| **резервная копия, к которой у агента нет доступа** | git-репозиторий (воркфлоу, промпты, набор, документы); опубликованные BRD — история версий документов Drive/wiki; агент не пишет в git и не удаляет документы | — |

### Проверка механизмов отката до пилота

Отметить, когда пройдено (выполняет владелец сервиса):

- [ ] `MAINTENANCE = true` → бот отвечает «Сервис временно недоступен», в executions нет вызовов модели → `false` → бот работает.
- [ ] `ROLLOUT_STAGE = shadow` → BRD в папке проверки, заказчику без ссылки, в чат команды «BRD в тени».
- [ ] `ROLLOUT_STAGE = hitl` → сессия `awaiting_review` → BRD-08 `approve` → документ в wiki, заказчику ссылка; второй BRD → BRD-08 `return` → заказчик получил вопросы, сессия `active`.
- [ ] Откат версии: импорт BRD-04 из предыдущего коммита → eval-набор BRD-97 → импорт текущей версии.
