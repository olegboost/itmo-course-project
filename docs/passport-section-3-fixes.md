# Паспорт, раздел 3: правки по замечанию ревьювера (2026-10-14)

Текста раздела 3 в репозитории нет, поэтому ниже готовые формулировки для строк, на которые указал ревьювер. Перенесите их в паспорт, подогнав под его таблицу.

## Строка 1 — доступы и права

> Pinecone: ключ API с полными правами (All). На плане Starter ограниченные роли (ReadOnly / ReadWrite) недоступны, они появляются с плана Standard. Компенсирующие меры: отдельный namespace `kb-brd-agent`; ключ хранится только в credentials n8n; писать в индекс может только BRD-01, а агенты обращаются к индексу только поиском. В закрытом контуре — роль только на чтение в pgvector/Qdrant для агентов и отдельная роль на запись для синхронизации.

Источник: [Pinecone — Manage API keys](https://docs.pinecone.io/guides/projects/manage-api-keys) («Starter and Builder plans can set the permissions to All only»).

## Строка 3 — где живёт результат и данные

> **Результат** — BRD в виде Google Doc в папке Google Drive «BRD Wiki».
> **Журналы и состояние** (не результат):
> - Google Sheets «BRD agent — logs»: `brd_registry` — реестр BRD, `brd_runs` — журнал прогонов, `manual_queue` — ручная очередь, `errors` — ошибки;
> - Data Tables n8n: `brd_sessions` — состояние интервью, `kb_files` — состояние базы знаний.
>
> **Каналы:** Telegram — бот для заказчика, чат команды, чат саппорта.

## Строка 5 — повтор («бот сформирует новую версию BRD»)

> Создание Google Doc — **класс повторяемости 3**: повтор создаёт второй документ. Защита:
> 1. у документа в `appProperties` записан ключ `brd_key = <session_id>#<номер попытки>`;
> 2. слепого повтора загрузки нет. Если загрузка вернула ошибку, сначала ищем документ по ключу: нашёлся — используем его, не нашёлся — делаем один повтор;
> 3. если и повтор не прошёл, текст BRD сохраняется в сессии, и повторный `/done` только публикует его.
>
> Генерация текста — **класс 1** (наружу ничего не ушло): при плохом ответе модели до 2 раундов перегенерации или исправления с текстом ошибки проверки, затем ручная очередь.
>
> Повторный `/done` от заказчика — новая попытка генерации, не больше 2 попыток на сессию (потолок control layer).

## Строка 6 — что получает пользователь

> Google Doc с BRD в папке «BRD Wiki» (ссылка открывается без доступа к остальному Drive). Дополнительно: строка в реестре `brd_registry`, ссылка заказчику в Telegram и уведомление «Новый BRD» в чат команды.

## Три числа паспорта

Верные числа: **5 раз в неделю, 240 минут на шаг, 6 прогонов до рабочего результата.** На них построены потолки control layer ([control-layer.md](control-layer.md)).

В **разделе 2** паспорта для шага 1 сейчас стоит «8 раз в месяц по 40 минут». Это ошибка расчёта, её нужно исправить на 5 раз в неделю по 240 минут. Если в разделе 2 «шаг 1» означает другой, более узкий шаг процесса, назовите его явно, чтобы числа не сравнивали напрямую.
