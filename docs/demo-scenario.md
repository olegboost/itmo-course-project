# Сценарий демонстрации

## 1. База знаний
1. Загрузите `kb-demo/knowledge-base/*` в папку KB и запустите **BRD-01 → Manual run**.
   Ожидаемо: в чате команды отчёт «Новых: 12…», в листе `kb_sync_log` строки `added`, в Pinecone (namespace `kb-brd-agent`) появились фрагменты.
2. Повторный запуск: отчёт «без изменений».
3. Замените в Drive файл DOC-09 версией из `kb-demo/updates/`: удалите старый и загрузите новый. Или откройте Google Doc и допишите вопрос.
   Запустите BRD-01 снова. Ожидаемо: `deleted` + `added` (или `updated` для правки Google Doc). Бот теперь знает про «8. Вопросы по BRD».

## 2. Интервью (роль заказчика — руководитель кредитования МСБ)
Реплики заказчика, по одной в ответ на вопрос бота:

1. `/start`
2. «Хотим каждую неделю прогнозировать, какие клиенты малого бизнеса уйдут из банка, чтобы менеджеры успели им позвонить.»
3. Если бот спросит про роль — «Я руководитель направления кредитования МСБ, бизнес.»
4. На вопрос о реестре — бот должен сам найти **SRV-002 «Прогноз оттока розничных клиентов»**. Ответ: «Он для физлиц, а нам нужны юрлица МСБ — это другое.»
5. «Модель уже обучили наши DS, лежит в MLflow, код в GitLab.»
6. «Результат — список клиентов с вероятностью ухода, его смотрят менеджеры в CRM.»
7. Про расписание/объём: «Раз в неделю, в понедельник утром, примерно 40 тысяч клиентов.»
8. Про ресурсы: «Не знаю, модель вроде небольшая, бустинг.» → бот должен предложить ориентир и спросить подтверждение, а не записать молча.
9. Про GPU: «Не нужен.»
10. Про данные: «Транзакции и продукты клиента из хранилища, там есть ИНН и данные директоров.» → бот фиксирует ПДн/банковскую тайну, меры защиты не предлагает.
11. Проверка закрытого контура: «А можно для объяснений результатов подключить ChatGPT?» → бот должен сказать о конфликте с закрытым контуром (риск в BRD).
12. Отвечайте ещё 2–4 вопроса (метрики, мониторинг), на один ответьте «не знаю» → открытый вопрос.
13. Когда бот пришлёт резюме — «Да, всё верно».

Ожидаемо: «Формирую BRD…», через 3–5 минут ссылка на Google Doc в папке BRD Wiki; в чате команды «Новый BRD»; строка в `brd_registry`; сессия `completed`.

Проверьте в документе: 13 разделов; в разделе 8 отмечены MLflow/GitLab; раздел 7.5 — только факты + «меры согласуются с ИБ»; риск про ChatGPT в разделе 9/11; ресурсы с пометкой «рабочая гипотеза»; «не знаю» — в разделе 11.

Голос: отправьте голосовое вместо текста на любом шаге — ответ должен учитывать его содержание.

## 3. Напоминания и дайджест
- В Data Table `brd_sessions` у активной сессии поставьте `last_activity_at` на 2 дня назад и запустите **BRD-05 → Manual run** → заказчику придёт напоминание с последним вопросом.
- **BRD-06 → Manual run** → дайджест в чат команды.

## 4. Алерты саппорту
- Временно испортите ключ в credential «cloud.ru API key (header)» и запустите BRD-01 после изменения файла → строки `error` в `kb_sync_log` и `errors`, алерт в чате саппорта. Верните ключ — следующий прогон переобработает файл.
- Испортите credential DeepSeek и напишите боту → заказчик получит извинение, саппорт — алерт с ID чата.
