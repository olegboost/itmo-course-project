# Лист потолков одного шага

Занятие 3.2.2 · практика занятия 5. Лист заполняется на **одном шаге** - том же, вокруг которого
собран паспорт инструмента с занятия 4. Результат ложится в этап 5 сквозного задания: обоснованные
значения потолков и ветка после предела - это то, что отличает верхний уровень позиции 5.3 от
середины.

Control layer (контрольный слой) вашего агента - это max steps, max cost и ветка fallback. Потолков,
которые огораживают прогон, четыре: **шаги · деньги · время · артефакты** (созданные файлы и записи).
Лист держит все четыре: значение каждого - не из воздуха, а из ваших чисел.

**Процесс (одной строкой):** ___________________________________________
**Шаг, который огораживаем (№ и формулировка из таблицы занятия 1):** ______________________
**Стек:** n8n · Langflow + Python · код · другое ____________ · **Дата:** __.__

## Лист

| шаг | что считаем | значение и откуда | что при достижении | кто разбирает очередь |
|---|---|---|---|---|
| образец ведущего: шаг 4 учебной цепочки «ИвентЛайн» | потолки прогона этого шага: шаги · деньги · время · артефакты | из сметы кейса: статья 3 - 950 000 ₽ · резерв - 570 000 ₽ · простой - 12 000 ₽/час → цена ошибки шага 4 | исход, не повтор: ветка fallback к человеку | роль с правом решить |
| ваш шаг | | | | |
| ваш шаг (следующий, если огораживаете несколько) | | | | |

Образец заполнен ведущим на занятии; строка «ваш шаг» - ваша. «Что при достижении» у всех
потолков одного шага обычно одна: исход ведёт к человеку (в очередь), а не в перезапуск прогона.

## Откуда брать значения

Три числа паспорта инструмента с занятия 4 - вход расчёта, они уже лежат в вашем документе:

| Число паспорта | Как становится потолком |
|---|---|
| сколько минут занимает сейчас | потолок времени: прогон не должен жить дольше, чем шаг стоил человеку, помноженный на разумный запас |
| сколько раз в неделю случается | частота превращает цену одного прогона в цену недели: потолок денег имеет смысл считать от неё |
| сколько прогонов до результата | потолок шагов: сколько кругов агенту позволено, пока вы не признали результат годным |

Дефолтные значения без обоснования стоят вдвое дешевле обоснованных: «так стояло в платформе» -
не обоснование. Обоснование - это число из вашего процесса и одна фраза, откуда оно.

Так устроен эталонный harness: у агента в mini-swe-agent (SWE-agent, лицензия MIT) ровно три
предела в одном конфиге - `step_limit`, `cost_limit`, `wall_time_limit_seconds`; исход после
предела остаётся задачей прогона. Permalink на коммит:
`github.com/SWE-agent/mini-swe-agent/tree/04d809c`, `src/minisweagent/agents/default.py` ·
проверено 09.09.2026.

## Что из этих чисел считает сам инструмент

Три числа паспорта - не все приходится вписывать руками:

- **«Сколько раз в неделю случается» - считает само, везде.** Claude Code: `~/.claude/stats-cache.json`
  (массив `dailyActivity`: прогоны, промпты, вызовы инструментов по дням) и `~/.claude/history.jsonl`;
  n8n: `GET /api/v1/executions` с фильтрами `startedAfter`/`startedBefore` или
  `GET /api/v1/insights/summary` (окно 7 дней); Langfuse: Metrics API v2, `count` с
  `granularity: week`.
- **«Сколько минут занимает сейчас» - наполовину.** Машинное время отдают все трое:
  `totalAPIDuration` + `totalToolDuration` в Claude Code, `stoppedAt − startedAt` в n8n, `latency`
  в Langfuse. Человеческого времени не отдаёт никто. Ловушка Claude Code: `totalDuration` - это
  время, что окно сессии было открыто (замер: 7 886 минут стены против 275 минут API в одной и той
  же сессии) - брать надо сумму API и инструментов.
- **«Сколько прогонов до результата» - не считает никто.** Ни в одном из трёх нет признака
  «получилось»: повтор с новым промптом неотличим от повтора того же (n8n связывает попытки
  `retryOf` только при явном ретрае из интерфейса; Langfuse не группирует по `sessionId` в Metrics
  API). Третье число упирается не в инструмент, а в то, что признак результата никто не назвал, -
  это ровно тема исхода: исход, который не различим, не существует.

Три оговорки, без которых обещание окажется ложным:

1. **n8n и Langfuse штатно не соединяются** («Currently, there is no native n8n tracing
   integration» - страница интеграции Langfuse); обходные пути - Broadcast на стороне OpenRouter,
   community-нода или сторонний OTEL-шиппер. Официальная нода `@langfuse/n8n-nodes-langfuse` -
   про управление промптами, не про трейсинг.
2. **Окна хранения.** n8n по умолчанию сносит прогоны через 14 суток (`EXECUTIONS_DATA_MAX_AGE`,
   336 часов) и после 10 000 записей; Insights собирает только продакшн-прогоны - кнопка Execute
   Workflow в редакторе в статистику не попадает. «Раз в неделю» посчитается, «раз в месяц» - если
   переменную не подняли заранее.
3. **Стоимость - оценка, не счёт.** `total_cost_usd` в Claude Code считается локально по
   прайс-таблице сборки; встроенный прайслист Langfuse покрывает не все модели, идущие через
   OpenRouter. Фактическую стоимость возвращает Usage Accounting в OpenRouter - она имеет приоритет
   над расчётной.

Связка Langflow ↔ Langfuse - штатная, тремя переменными окружения (документация Langfuse, раздел
Langflow), работает с langflow 1.0.17. Полный разбор наблюдаемости - занятия 6 (cost control) и
10 (eval).

## Где живёт денежный потолок (max cost)

Денежный потолок назовите числом и покажите, где он поставлен в вашем контуре. **В n8n и LangFlow
денежного потолка внутри сценария нет: это лимит ключа у провайдера, а не настройка в конструкторе -
что умеет ключ, то и умеет агент.**

| Ваш стек | Где стоит денежный потолок | Что показать в сдаче |
|---|---|---|
| n8n | лимит ключа OpenRouter или лимит ключа у провайдера модели | число и снимок настройки лимита |
| LangFlow | там же, у провайдера ключа | число и снимок настройки лимита |
| код | свой счётчик расхода в коде или лимит ключа | число и место в коде либо снимок |
| шлюз (LiteLLM и подобные) | бюджет сессии на шлюзе | число и настройка шлюза |

`max steps` и ветка `fallback` при этом задаются именно в самом сценарии - для них требование
читается буквально.

Первоисточник правила: лимит на ключ - простейший жёсткий потолок («A per-key limit is the
simplest hard cap. It limits one API key, and you don't need an organization to use it»,
OpenRouter, «Governing AI Spend Across a Team», 06.08.2026,
`openrouter.ai/blog/insights/governing-team-ai-spend`); поля `limit` / `limit_remaining` /
`limit_reset` - в справочнике `openrouter.ai/docs/api_reference/limits`. Проверено 09.09.2026.

## Чек-лист строки

- У каждого из четырёх потолков стоит число и источник числа.
- Денежное число показано там, где оно реально стоит (лимит ключа, счётчик, шлюз).
- После достижения любого потолка прогон уходит в очередь к роли с правом решить - не в повтор.
- Лист заполняется без выключения потолков: лист и последующий cost-attack делают на одних и тех же
  значениях.
